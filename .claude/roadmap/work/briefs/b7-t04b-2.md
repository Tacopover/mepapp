GOAL: A new hook `useRiserFlowInputs` is the one place that calls `scene.setRiserFlowInputs`. It is wired in `App.tsx`. After it, when a building with risers is open, the capacity numbers of the open level count the other levels. It also returns the solve result for the Properties panel (brief 3 uses it).

CONTEXT: Brief 1 made `packages/ui/src/riserFlowSync.ts` (`computeRiserFlow`, `RiserFlowSender`, `sameRiserFlowInputs`; read it first). The scene resets its riser flow inputs on `pageChanged` and on `documentActivated` and nothing re-sends them. `setRiserFlowInputs` calls `recomputeFlow`, which emits `flowSolved`. So the hook must NEVER listen to `flowSolved` (loop). `drawingChanged` is emitted for each edit and during a drag, so the heavy work is debounced. `buildRiserNetworks` (core) runs `computeNetworks` and `solveFlow` per network: it is the heavy part.
Facts you can rely on: `BuildingController.reload()` and `refreshSheetStatus()` run after every write of a stored summary (save, summary on open, "Read summaries now"); `building.sheetSummary[sheetId].savedAt` changes then. So a signature of the `savedAt` values is the trigger "the stored summaries changed". `readSummaries(store)` is in `./quantitiesScope.js` and returns `{ summaries: Map<projectUuid, SheetSummary>, problems }`. `activeSheetOf` is in `./riserActions.js`. `useBuildingRisers.ts` (lines ~674-689) shows how the scene events are subscribed (`scene.on('documentActivated', fn)` and `scene.off`). The open document and page: `scene.getProjectUuid()` and `scene.getPageIndex()`.

EXACT SHAPES:
```ts
import type { BuildingFlowResult, SheetSummary } from '@mepapp/core';
import { buildRiserNetworks } from '@mepapp/core';

export interface RiserFlowState {
  /** Id of the sheet of the shown page. */
  sheetId: string;
  flow: BuildingFlowResult;
}

/** The delay after a drawing edit. A drag emits many edits. */
export const EDIT_DELAY_MS = 200;
/** The delay after a page change, a document change, a change of the building file or of the stored summaries. */
export const SWITCH_DELAY_MS = 60;

export function useRiserFlowInputs(args: { sceneRef: RefObject<SketchScene | null>; ready: boolean; building: OpenBuilding | null }): RiserFlowState | null
```
Behavior (all of it):
1. State: `const [state, setState] = useState<RiserFlowState | null>(null)`. Refs: `summaries` (`ReadonlyMap<string, SheetSummary> | null`, null = not read yet), `sender` (`new RiserFlowSender()`), `timer`, `stateKey` (string of the last state: `JSON.stringify([sheetId, flow])`, so an equal result does not set state again), `live` (`{ file, store }`, updated at each render, like `live.current = ...` in useBuildingRisers).
2. `run()` (no arguments; reads only refs and the scene; wrapped in try/catch: on an error call `console.warn('Riser flow inputs failed', error)` and return): 
   - `scene = sceneRef.current`; return if null.
   - `{ file }` = live; `computed = summaries.current === null ? null : computeRiserFlow({ file, projectUuid: scene.getProjectUuid(), pageIndex: scene.getPageIndex(), summaries: summaries.current, liveNetworksOf: (ids) => buildRiserNetworks(scene.exportProject(), ids) })`.
   - If `file` has risers and `summaries.current === null`: return (not read yet; the read triggers a new run). Otherwise:
   - `const toSend = sender.next(computed?.inputs ?? {})`; `if (toSend !== null) scene.setRiserFlowInputs(toSend)`.
   - Set the state: key = computed ? JSON.stringify([computed.sheetId, computed.flow]) : ''; if key differs from `stateKey.current`: set `stateKey.current = key` and `setState(computed ? { sheetId: computed.sheetId, flow: computed.flow } : null)`.
3. `schedule(delay)`: `clearTimeout(timer.current)`; `timer.current = window.setTimeout(run, delay)`. Keep a stable `scheduleRef` if needed by the effects.
4. Effect 1 (summaries), deps `[building?.store, summarySignature]` where `summarySignature = JSON.stringify(Object.entries(building?.sheetSummary ?? {}).map(([id, info]) => [id, info.savedAt]))`: if there is no store: `summaries.current = null` and `schedule(SWITCH_DELAY_MS)`; return. Else call `readSummaries(store)` (a request counter drops an older answer); on success `summaries.current = result.summaries`; on failure `summaries.current = new Map()`; then `schedule(SWITCH_DELAY_MS)`. A new store (another building) sets `summaries.current = null` at once before the read.
5. Effect 2 (building file), deps `[ready, building?.file]`: `schedule(SWITCH_DELAY_MS)`. This covers a change of the riser list, of the sheets, and a building that closes (then `run` sends `{}` once when the scene still holds inputs).
6. Effect 3 (scene events), deps `[ready, sceneRef]`: when `ready` and the scene exist: `onEdit = () => schedule(EDIT_DELAY_MS)`; `onSwitch = () => { sender.current.reset(); stateKey.current = ''; setState(null); schedule(SWITCH_DELAY_MS); }`. Subscribe `drawingChanged` -> onEdit; `documentActivated` and `pageChanged` -> onSwitch. Cleanup: off for all three and `clearTimeout`. NEVER subscribe to `flowSolved`.
7. The hook calls `scene.setRiserFlowInputs` in exactly one place (inside `run`).
Follow the style of `useBuildingRisers.ts` (imports, `live.current = ...`). Keep the file under about 130 lines.
