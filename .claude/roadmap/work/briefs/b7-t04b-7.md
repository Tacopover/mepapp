# B7-T04b brief 7: fixes after the UI review (ui)

Read .claude/roadmap/rules.md first.

GOAL: Four small fixes of the riser block of the Properties panel.

CONTEXT: The UI review found: (1) When the level that holds the source has no saved summary, the row reads `not known yet (no source level)` and the hint F tells the user to set the main level, but the real cause is missing data. (2) The tag `Not a design flow` has no space below it and touches the first row. (3) The heading `Riser R1` has no `title`, so a long riser name that wraps is not readable in full. (4) The value text has a dotted underline like a disabled input, and the line has an uneven length; it looks like a field but it is only text.

TARGETS: `packages/ui/src/riserCapacity.ts`, `packages/ui/src/riserCapacity.test.ts` (add tests, do not edit existing ones), `packages/ui/src/components/PropertiesPanel.tsx`, `packages/ui/src/theme.css`.

EXACT SHAPES:
1. In `fittingRiserLinesOf` (riserCapacity.ts): let `noData = view.unknown && !view.complete && view.unknownReasonText === REASON_TEXT['no-source']`. When `noData` is true: the Main level row value is `not known yet (a level has no data)` (title `Main level: not known yet (a level has no data)`) and the hint F is NOT added (the hint E stays; it tells the user to open Manage Buildings, tab Risers, to see which levels). In every other case nothing changes (including: unknown and not complete with another reason; unknown and complete with reason `no source level`: row `not known yet (no source level)` and hint F as now). The hint order does not change. `capacityViewOf` and the T05 texts do not change.
2. theme.css: after the `.mep-rp-tag` rule add `.mep-section > .mep-rp-tag { margin-bottom: 6px; }`.
3. PropertiesPanel.tsx: the heading line becomes `<h4 title={riserLines.heading}>{riserLines.heading}</h4>`.
4. theme.css: in the rule `.mep-field-text` (added by brief 4) delete the line `border-bottom: 1.5px dotted var(--ink);`. Keep everything else.
Tests to add in riserCapacity.test.ts (describe 'fittingRiserLinesOf'): (a) a view with unknown true, complete false, unknownReasonText `no source level`: main row value `not known yet (a level has no data)`, hints contain the E text and not the F text; (b) unknown true, complete TRUE, reason `no source level`: row `not known yet (no source level)` and the F text is present (unchanged); (c) unknown true, complete false, reason `more than one source level`: row `not known yet (more than one source level)`, both E and F present. Build the views as literal `CapacityView` objects (copy the shape used by the existing literal-view tests of the file).
