# Brief B3-T13c-1: minted sheet ids (core + pure UI logic)

Read .claude/roadmap/rules.md first. Work only in /root/MepApp/.claude/worktrees/buildings-model. One command per Bash call. No chained commands, no heredocs, no prettier, no pnpm add.

## GOAL
A PDF that holds no project id gets a minted id when it is added to a level. The sheet keeps the id and a flag `idMinted: true` (the PDF does not hold the id yet). A new status 'not-opened' shows for such a sheet until a summary exists. The flag is cleared when a save writes the id into the PDF. No file on disk changes.

## CONTEXT
- `BuildingSheet` (packages/core/src/building.ts:24) has `projectUuid: string | null`. Unknown fields stay in a parsed building file, so an optional field needs no schema bump.
- `addSheets` (packages/core/src/building-edit.ts:56) builds the sheets from `NewSheetPage[]`.
- `placeEntriesOnLevel` (packages/ui/src/buildingSheets.ts:159) puts pending PDFs on a level. `PendingPdf.projectUuid` is null for a PDF without an embedded id. One PDF = one id for all its pages.
- `findSheets(file, {projectUuid, path, fileName, sizeBytes})` (packages/core/src/building-identity.ts:34) returns matches with strength 'id' | 'path' | 'weak'. With projectUuid null a sheet matches by path or by (fileName + sizeBytes).
- `summaryAfterSave` and `linkSheetsWithRetry` are in packages/ui/src/buildingContext.ts. `sheetStatusOf` is in packages/ui/src/buildingStatus.ts.

## TARGETS (edit only these; add tests next to the code)
Core:
1. packages/core/src/building.ts: add to `BuildingSheet`: `/** true: the app made projectUuid and the PDF does not hold it yet. Absent once a save wrote the id into the PDF. */ idMinted?: true;`
2. packages/core/src/building-edit.ts:
   - `NewSheetPage` gets `idMinted?: true`. `addSheets` copies `idMinted: true` onto the new sheet only when `page.idMinted === true && page.projectUuid !== null`.
   - `export function withIdInFile(file: BuildingFile, projectUuid: string): BuildingFile` removes `idMinted` from every sheet with that projectUuid. Returns the same object when no sheet has the flag with that id.
   - `export function replaceMintedId(file: BuildingFile, fromUuid: string, toUuid: string): BuildingFile` sets projectUuid = toUuid and drops `idMinted` on the sheets that have `projectUuid === fromUuid && idMinted === true`. Returns the same object when there is none, when from === to, or when a sheet outside that set already has toUuid on a pageIndex that the renamed set uses (a duplicate would result).
   - Tests in packages/core/src/building-edit.test.ts (addSheets keeps the flag; not for null id; withIdInFile; replaceMintedId incl. the three no-op cases).
UI:
3. packages/ui/src/buildingSheets.ts:
   - `PendingPdf` and `PdfGroup` get `idMinted?: true`. `groupPdfs` copies it from the pending PDF to its group. `newSheetPage` adds `idMinted: true` when `group.idMinted === true && group.projectUuid !== null`.
   - New exported `resolveEntryIds(file: BuildingFile, entries: readonly PendingPdf[], makeId: () => string): { file: BuildingFile; entries: PendingPdf[] }`. For each entry:
     a. matches = `findSheets(file, { projectUuid: null, ...(path), fileName, sizeBytes })` without a 'weak' match when both the entry and the sheet have a path.
     b. entry.projectUuid is a string: for each match whose sheet has `idMinted === true` and `projectUuid !== entry.projectUuid`, `file = replaceMintedId(file, sheet.projectUuid, entry.projectUuid)` (embedded id wins). Entry unchanged.
     c. entry.projectUuid is null and a match has a non-null projectUuid: the entry takes that projectUuid and that sheet's idMinted flag.
     d. entry.projectUuid is null and a match has a null projectUuid: entry unchanged (old data, stays unlinked).
     e. entry.projectUuid is null and no match: `projectUuid = makeId()`, `idMinted: true`.
     Entries are handled in order; an id minted for an earlier entry is never reused for a later one (each makeId() call is for one PDF).
   - `placeEntriesOnLevel(file, entries, levelId, makeId = () => crypto.randomUUID())` calls `resolveEntryIds` first and uses its file and entries for everything else. The returned `file` is the result of addSheets on the resolved file. Keep the return shape.
   - Tests in packages/ui/src/buildingSheets.test.ts: mint for a PDF without id (all pages share one id, flag set); a second add of the same PDF (same path) reuses the id and reports pages as already on the level (no second id); two different PDFs get two ids; null-id old sheets are not given an id; embedded id replaces a minted id; a PDF with an embedded id is unchanged and has no flag.

Tone 'warn'. `sheetsWithoutSummary` leaves out 'not-opened' (a read cannot fix it). `otherNoSummaryText`: say "its PDF is missing, has no access, is not opened yet, or is not checked yet" (singular) and the plural form "their PDFs are missing, have no access, are not opened yet, or are not checked yet". Update the doc comment of sheetStatusOf. Update the exhaustive tests in packages/ui/src/buildingStatus.test.ts and add tests.
