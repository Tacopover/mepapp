# Brief B3-T13c-3: wire the minted ids into the app

Read .claude/roadmap/rules.md first. Work only in /root/MepApp/.claude/worktrees/buildings-model. One command per Bash call. No chained commands, no heredocs, no prettier. No window.confirm.

## GOAL
When a document opens (Menu > Open, the dialog Open button, Open with) and its PDF holds no id, but a sheet with a minted id (`idMinted: true`) matches it by path (or by file name + size when no path), the document adopts the sheet id. Then the summary is written at once and the sheet shows OK. A save later writes the id into the PDF and clears the flag (already done in `summaryAfterSave`).

## CONTEXT (all exist already)
- `matchingMintedIds(file, {path, fileName, sizeBytes}): string[]` and `mintedAdoptions(file, docs, targets)` in packages/ui/src/adoptSheetId.ts.
- `replaceMintedId(file, from, to)` in @mepapp/core.
- `scene.commitProjectUuid(documentId, projectUuid, { inFile: false })` (packages/render/src/scene.ts:4250) sets the document id without claiming the file holds it. App.tsx:2208 already uses it.
- `summaryAfterSave({... idInFile?: boolean })` (idInFile default true).
- `documentOpenedRef.current` in packages/ui/src/App.tsx:779 runs after loadFromPdf. `writeSummaryOnOpen` is at :691. `shouldWriteSummaryOnOpen` (summaryOnOpen.ts) refuses when `projectUuidInFile` is false. The `duplicatePrompt` state is at :475.
