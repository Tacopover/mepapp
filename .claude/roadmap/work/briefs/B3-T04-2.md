GOAL: The Manage Buildings dialog has a "Sheets" pane: the user adds PDFs (one file, or a folder on desktop), sees each PDF with a row for each page, and picks a level for each page. Choosing a level creates or moves the sheet in the building file; choosing "Not assigned" removes it.

CONTEXT: Brief B3-T04-1 already made two pure modules (read them first): `packages/ui/src/buildingPdfInfo.ts` (`BUILDING_PDF_TYPES`, `readPdfInfo(file, engine)`, `pathOfTarget(target)`, `joinFolderPath(folder, name)`) and `packages/ui/src/buildingSheets.ts` (`PendingPdf`, `PdfGroup`, `PageRow`, `groupPdfs(file, pending)`, `newSheetPage(group, pageIndex)`, `isSamePdf`, `pdfTotals`, `sheetDisplayName`, `COLLAPSE_AFTER_PAGES`). Unassigned pages are not stored (decision D-B-17 A): `BuildingSheetsPane` keeps the added PDFs as `PendingPdf[]` in React state; closing the dialog drops them; sheets stay in the building file. Core edit functions (`@mepapp/core`, `building-edit.ts`): `addSheets(file, levelId, pages): {ok:true,file,skipped} | {ok:false,error}`, `moveSheet(file, sheetId, levelId)`, `removeSheet(file, sheetId)`. All changes go through `update(change)` (see `BuildingLevelsPane.tsx`, which you copy in style). Picking a file: `fileAccess.openFile(BUILDING_PDF_TYPES)` returns `OpenedFile {file, target?}` or undefined on cancel; the picker call must be the first `await` in the click handler. Folder: `fileAccess.pickFolder()` returns `{name, folder: LibraryFolderRef}` or undefined; then `fileAccess.readFolder(folder, ['pdf'])` returns `File[]`; when `'folderPath' in folder` the path of each file is `joinFolderPath(folder.folderPath, file.name)`, else no path. Types come from `@mepapp/platform` (`FileAccess`) and `@mepapp/pdf-engine` (`PdfEngine`).
