GOAL: A relink must not create two sheets with the same document id and page (the building file parser refuses such a file: "one sheet per (projectUuid, pageIndex)"). The pane refuses and tells the user.

CONTEXT: `packages/ui/src/components/BuildingSheetsPane.tsx` has the relink flow (`relink(group)` and `applyRelink` / `confirmRelink`), which calls `update((f) => ids.reduce((acc, id) => relinkSheet(acc, id, location, uuid), f))` where `uuid` is the id read from the picked PDF (or undefined). `relinkSheet` (core `building-edit.ts`) sets `projectUuid` only when `uuid !== undefined`. A browser check found a React warning "two children with the same key 0": the page rows of a group use `key={row.pageIndex}`, and two sheets with the same page index landed in one group after a relink.

TARGETS:
1. `packages/ui/src/buildingSheets.ts` add and export:
```ts
/** True when giving the sheets `sheetIds` the document id `projectUuid` would leave two sheets with the same non-null id and page index. projectUuid undefined or null -> false. Sheets outside sheetIds keep their id. */
export function relinkWouldDuplicate(file: BuildingFile, sheetIds: readonly string[], projectUuid: string | null | undefined): boolean;
```
   with tests in `buildingSheets.test.ts` (no id -> false; same id and same page as another sheet -> true; same id, other page -> false; two sheets of the relinked set with the same page index and the new id -> true; a sheet already carrying the id that is itself in sheetIds does not conflict with itself).

3. `BuildingSheetsPane.tsx`: page row key becomes `row.sheet?.id ?? \`page-${row.pageIndex}\``.
