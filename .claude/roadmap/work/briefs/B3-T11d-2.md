## CONTEXT: the new DOM contract (T11d)
- The levels table is gone. Levels are edited in ONE detail pane for the SELECTED level. There is exactly one `[data-testid="level-row"]` (for the selected level), holding `input[aria-label="Level name"]`, `input[aria-label="Elevation (mm)"]`, `button[aria-label="Move level up"]`, `button[aria-label="Move level down"]`, and a `button` with text `Delete`.
- To edit level i: click the tree item `dlg.locator('[role="treeitem"][data-kind="level"]').nth(i)` (it has `data-testid="tree-level"`), wait ~300 ms, then use the single `level-row`. Tree level items show the name in `.mep-tree-label`.
- "Add level" is now a tree item: `dlg.locator('[data-testid="tree-add-level"]')` (role treeitem, text `+ Add level`). Click it. The new level is created with the default name "Level N", it becomes the SELECTED level, and its name input has the focus with the text selected. Typing replaces the default name.
- Delete: a `button` `Delete` with `aria-disabled="true"` (not `disabled`) when the level has sheets; Playwright `isDisabled()` still returns true for it. The reason is visible text in `[data-testid="delete-reason"]`: "Remove its 1 sheet first" / "Remove its 2 sheets first". The old title text "This level has 1 sheet..." is gone (the title now equals the new reason text).
- Deleting an empty level has no confirm. A line `[data-testid="level-undo"]` appears for 8 s with a button `Undo`. After a delete the next level (or the previous, else the building) is selected.
- "Sort by elevation" button: `aria-disabled="true"` when already sorted (reason in `[data-testid="sort-reason"]`: "Levels are already in order of elevation."). `isDisabled()` still works.
- The "No levels yet" hint now reads "No levels yet. Use + Add level in the tree." (the regex `/No levels yet/` still matches).
- Level order in the tree = order in the file. Moving a level keeps it selected.
- `[data-testid="selection-summary"]` is unchanged.
