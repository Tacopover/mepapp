# B3-T13a-3: sheets under the levels in the left tree, no "Open" badge

Read .claude/roadmap/rules.md first. Work only in /root/MepApp/.claude/worktrees/buildings-model.

GOAL
1. The left tree (ARIA tree) shows the sheets (PDF file names) under each level. Levels are COLLAPSED by default. Each level with sheets has its own expand/collapse arrow.
2. The "Open" badge next to the open building is removed.

EXACT SHAPES
- `TreeNodeKind` adds `'sheet'`. `TreeNode.depth` becomes `1 | 2 | 3`. Add to TreeNode `sheetId: string | null` (null for other kinds). Sheet key: `export const sheetKey = (id: string): string => \`s:${id}\``.
- `TreeInput` adds `expandedLevels: ReadonlySet<string>` (level keys "l:<id>" that the user expanded; default none = collapsed).
- A level node: `expandable = it has at least one sheet`, `expanded = expandable && expandedLevels.has(key)`. When expanded, its sheet nodes follow it (depth 3, parentKey = level key, kind 'sheet', order = `sheetGroupsOfLevel(file, levelId).flatMap(g => g.sheets)`), before the next level.
- Sheet node: `label = sheet.location.fileName`; `detail = \`p. ${pageIndex + 1}\`` when the PDF has more than one sheet in the building (`sheetsOfSamePdf(file, sheet).length > 1`) or pageIndex > 0, else null; `warning = status tone 'bad'` (Missing, No access) for that sheet only; `isOpen=false, expandable=false, expanded=false, entry=null`. One node per sheet (no PDF grouping node).
- `moveFocus`: ArrowRight on a collapsed expandable level expands it; on an expanded level moves to its first child (existing generic logic already does this: keep it working for depth 3). ArrowLeft on an expanded level collapses it; on a sheet node moves to its level (parentKey). ArrowUp/Down walk visible nodes; Home/End unchanged. Update the doc comment `FocusMove.toggle` ("a building or a level").
- BuildingTree.tsx: remove the Open badge (delete the `mep-tree-badge` span and its CSS rules in theme.css, both `.mep-tree-badge` blocks). Do not replace it with anything except: the label of the open building may get `font-weight: 600` through a modifier class `mep-tree-item--open` on the building item (CSS only, no new word). The arrow becomes a real button for expandable nodes: `<button type="button" className="mep-tree-arrow" tabIndex={-1} aria-label={\`${expanded ? 'Collapse' : 'Expand'} ${node.label}\`} aria-expanded={node.expanded} onClick={stopPropagation; onToggle(node.key, !node.expanded)}>`. Clicking the arrow of a level must not change the selection and must not call onActivate. Keep `aria-expanded` also on the treeitem (role tree validity). A button inside a treeitem is acceptable because it has tabIndex -1; keep `aria-hidden` off it.
- Sheet items: class `mep-tree-item--sheet`, `title={label}` (also set title on level/building labels when cut), label with ellipsis (CSS `overflow:hidden; text-overflow:ellipsis; white-space:nowrap; min-width:0`). Status dot (`mep-tree-dot`, role img, aria-label "This sheet has a missing PDF or no access") only when `warning`. The level's own warning dot stays. Sheet count `detail` shows as the quiet `mep-tree-count`.
- Dialog (ManageBuildingsDialog.tsx): new state `const [expandedLevels, setExpandedLevels] = useState<Set<string>>(() => new Set())`, reset to a new Set when the opened building id changes (where `setCollapsed(new Set())` is). `onToggle(key, expand)`: if `key` starts with `l:` update expandedLevels only (no change of selection); else the existing building logic. Pass `expandedLevels` to `buildTreeNodes`.
- Sheet node activation (`onActivate` with `node.kind === 'sheet'`): select its LEVEL (`setSelectedKey(node.parentKey)`), `setFocusKey(node.key)`, and set highlight state `setHighlight({ sheetId: node.sheetId!, seq: n + 1 })`. Any other activation clears the highlight (`setHighlight(null)`). Do not call this when `building.busy`.

- LevelSheetsPane gets a new optional prop `highlight?: { sheetId: string; seq: number } | null`. The row of that sheet gets `data-highlight="true"` (and a CSS class `mep-srow--pick`, a quiet background plus outline, in theme.css next to .mep-srow) and an effect on `highlight?.seq` calls `scrollIntoView({ block: 'nearest' })` on that row (guard `typeof el.scrollIntoView === 'function'`). Clear the highlight with a click anywhere else is NOT needed; it clears on the next activation. The highlight shows only when the pane lists that sheet.
