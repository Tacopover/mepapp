## GOAL
In `solveFlow` (packages/core/src/flow.ts), the highest-rule branch (the `if (input.highestWhenNoSource && ...)` block, lines ~172-192) must take the other levels into account through "sides" of marked riser fittings. Today it ignores `riserDemand` and returns `riserCapacity` 0.

## CONTEXT
Plan: .claude/plans/buildings-b7-t09-open-ends.md sections 2 (Examples 2, 3, 5), 3.4, 3.5 and the task "B7-T09a-3". `highestFlow(nodes, edges)` in `packages/core/src/flow-highest.ts` is done. It takes `{id, own, roots}` nodes and `{id, a, b}` edges and returns `{ total, roots, edge, node, sides } | null`.

A marked riser fitting (key `fitting:<id>`, in `input.riserFittingIds`) with one segment gets "sides". A side is `{ demand, openEnds }`: terminal capacity and number of open ends on the far side of one span, seen from this level. In the branch each side becomes an extra node (`own` = demand, `roots` = openEnds) joined to the fitting by one extra edge. The marked fitting itself stays a node with `roots` 0 (as now: `isOpenEndKey` excludes marked ids).

Today the code uses `withRiserCapacity(..., 0)`, which only sets the key when `riserDemand` is defined. Write the mapping so `riserSides` alone also sets it. Do not change `withRiserCapacity` use in the old path.
