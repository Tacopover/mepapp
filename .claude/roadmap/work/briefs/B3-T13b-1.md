# GOAL
Add a multi-file picker to FileAccess: new method `openFiles`. The old `openFile` stays for other callers.

# CONTEXT
"Add PDFs…" in the Building dialog must let the user pick more than one PDF. Today FileAccess has only `openFile` (single). UI code (another worker, later) will call `fileAccess.openFiles(BUILDING_PDF_TYPES)`.
Existing code:
- packages/platform/src/file-access.ts: interface FileAccess (openFile at line 43).
- packages/platform-web/src/web-file-access.ts: `pickWithFileInput(types)` returns `Promise<File | undefined>`; `openFile` uses `window.showOpenFilePicker!({ types: pickerTypes(types) })`. `FileSystemAccessOpenOptions` already has `multiple?: boolean`.
- packages/platform-tauri/src/tauri-file-access.ts: `openFile` uses `open({ multiple: false, directory: false, filters })` from @tauri-apps/plugin-dialog; with `multiple: true` the plugin returns `string[] | null`. Capability `dialog:default` already allows open; no capability change.

# TARGETS

# EXACT SHAPES
In the interface (after openFile):
```ts
  /** Like openFile, but the user can pick several files. Resolves to an empty array when the user cancels. */
  openFiles(types: FileTypeFilter[]): Promise<OpenedFile[]>;
```
Web:
- Change `pickWithFileInput(types, multiple)` to return `Promise<File[]>` (empty when cancelled), set `input.multiple = multiple`; `change` resolves `[...(input.files ?? [])]`. `openFile` keeps its behaviour (uses `(await pickWithFileInput(types, false))[0]`).
- `openFiles`: no File System Access -> `(await pickWithFileInput(types, true)).map((file) => ({ file }))`. Else `showOpenFilePicker({ types: pickerTypes(types), multiple: true })`, map each handle to `{ file: await handle.getFile(), target: handle }`; AbortError -> `[]`; other errors rethrown (same as openFile).
Tauri:
- `openFiles`: `const paths = await open({ multiple: true, directory: false, filters: dialogFilters(types) });` null or empty -> `[]`. Set `this.lastDirectory = await dirname(paths[0])`. For each path return `{ file: await readAsFile(path, mimeTypeFor(path, types)), target: { name: baseName(path), path } }` (PathTarget). Keep the order of the picker.

Tests (web-file-access.test.ts, same style; use `vi.stubGlobal('window', {...})` and unstub after each test):
1. openFiles passes `multiple: true` to showOpenFilePicker and returns one `{file, target}` per handle in order.
2. openFiles returns [] when showOpenFilePicker rejects with `new DOMException('x', 'AbortError')`.
3. openFile still passes no `multiple: true` and returns the first handle's file.
(`WebFileAccess` is the class; `window.showOpenFilePicker` is the stub; handle = `{ name, getFile: async () => new File(['x'], name) }`.)
