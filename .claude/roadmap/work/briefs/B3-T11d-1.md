# Brief B3-T11d-1: levels in the tree

Read .claude/roadmap/rules.md first. Worktree: /root/MepApp/.claude/worktrees/buildings-model (work only there). One Bash command per call, no chaining, no heredocs, no prettier, no pnpm add, no window.confirm.

## GOAL
The Manage Buildings dialog edits levels through the tree and one detail pane. The old multi-row levels table goes away. Add level sits in the tree. Delete of an empty level has an 8 s Undo line. Delete and Sort show their reason as visible text.

## CONTEXT
- packages/ui/src/components/ManageBuildingsDialog.tsx renders BuildingTree (left) and, on the right, a selection summary, `<BuildingLevelsPane ...>` (marked "T11d replaces this pane"), BuildingSummariesPane, BuildingSheetsPane. Do not touch the last two.
- BuildingLevelsPane.tsx today lists every level as a row (`data-testid="level-row"`), with LevelNameInput and LevelElevationInput (draft until blur/Enter, Escape drops), up/down buttons, Delete, "Add level", "Sort by elevation", and levelWarnings. Keep LevelNameInput and LevelElevationInput logic.
- Core (`@mepapp/core`): `addLevel(file, name, elevationMm?, id?)` (blank name -> `Level ${levels.length+1}`), `deleteLevel(file, id)` returns {ok,file}|{ok:false}, `moveLevel(file, id, toIndex)`, `sortLevelsByElevation`, `levelWarnings`. `building.update(change: (file)=>file): Promise<void>`.
- buildingTree.ts: `TreeNode`, `buildTreeNodes`, `moveFocus`, `levelKey(id)` = `l:<id>`, `buildingKey(id)`. BuildingTree.tsx is a flat ARIA tree with roving tabindex; Enter/Space calls `onActivate(node)`.

/** null when the level can be deleted; else "Remove its 2 sheets first" / "Remove its 1 sheet first". */

Behavior:
1. Selected level: ONE block `data-testid="level-row"` (class `mep-level-detail`) with labelled fields: "Name" (input aria-label "Level name"), "Elevation (mm)" (input aria-label "Elevation (mm)", unit text mm), buttons `aria-label="Move level up"` / `"Move level down"` (disabled at ends, keep arrows as text), and a `Delete` button (text "Delete"). Key the inputs by level id so a draft never carries to another level. When `focusNameLevelId === level.id` focus the name input and `select()` its text in an effect, then call `onNameFocused()`.
2. Delete: when `deleteBlockedText` is not null the button has `aria-disabled="true"` (NOT `disabled`, so it stays in the Tab order), `title` = the same text, ignores clicks, and the text shows next to it in `<p className="mep-hint" data-testid="delete-reason">`. When allowed: click deletes (no confirm) with `update(f => deleteLevel...)`, then selects the next level (levels[index+1] ?? levels[index-1]) or the building (`buildingKey(file.id)`) through `onSelectKey`, and shows the Undo line.
3. Undo line (state in the pane; pane is keyed by `file.id` in the dialog so it resets on a building change): `<p role="status" data-testid="level-undo" className="mep-hint mep-buildings-message">Deleted level "NAME". <button type="button">Undo</button></p>`. It disappears after 8000 ms (setTimeout, cleared on unmount and on a new delete), after Undo, and when another level is deleted (the new line replaces it). Undo runs `update(f => restoreLevel(f, level, index))` and `onSelectKey(levelKey(level.id))`.
4. Always (also when no level is selected but the file has levels): a "Level order" block with the button "Sort by elevation" (`aria-disabled` + title when `sortBlockedText` is not null, click ignored then) and the reason as `<p className="mep-hint" data-testid="sort-reason">` when blocked. Under it the `levelWarnings` lines as today.
5. With no levels: hint "No levels yet. Use + Add level in the tree." No Add button here.
6. Remove the head row, the sheet-count column and the "cannot delete" text.
