# Brief B3-T11f-1: unit tests for openDocumentAdd

Read .claude/roadmap/rules.md first. Work in /root/MepApp/.claude/worktrees/buildings-model only.

GOAL: Write vitest tests for the new pure module `packages/ui/src/openDocumentAdd.ts` (`addOpenDocumentPages`, `openDocumentNewPage`).

CONTEXT: The module puts the pages of one open document on a level. It re-reads the row state from the file with `openDocumentRows` (packages/ui/src/openDocumentsView.ts), so a second call adds nothing twice. Copy the helpers `sheetOf`, `buildingOf`, `docOf` from `packages/ui/src/openDocumentsView.test.ts` (top 30 lines). Make rows with `openDocumentRows([doc], targets, file)` where `targets` is `new Map([[id, {name:'a.pdf', path:'/x/a.pdf'}]])` or `new Map()`. Use a building with two levels L1 'Ground' and L2 'First'.

TARGETS: create `packages/ui/src/openDocumentAdd.test.ts` only.

EXACT SHAPES (tests, each one `it`):
1. add one page of a 3-page doc with id (projectUuidInFile true): file gets 1 sheet, levelId L1, projectUuid = the id, pageIndex, displayName 'a.pdf p2', location {fileName, path, sizeBytes}; result `added` 1.
2. add all 3 pages: 3 sheets, added 3.
3. already placed on L1: second call returns added 0, moved 0 and `result.file === file` content-equal (sheets length unchanged).
4. page placed on L2, call with levelId L1, move=false: nothing changes; with move=true: sheet levelId becomes L1, moved 1, added 0.
5. doc with no id (projectUuidInFile false, projectUuid 'minted') and a path: new sheet has projectUuid null, location.path set.
6. doc with no id and no path: first call adds 1 sheet with projectUuid null and no `path` key; apply the call again on the resulting file with the SAME original row: adds 0 (sheets length stays 1).
7. double call with id: call twice in a row on the result of the first: total sheets stay equal.
8. unknown level id: returns the same file, added 0.
9. `openDocumentNewPage` omits `sizeBytes` when `doc.sizeBytes` is null.

DO NOT TOUCH: any file except the new test file. Do not change the module under test; if a test shows a bug in it, report it as BLOCKED with the evidence.

VERIFY: run `pnpm --filter @mepapp/ui test` and `pnpm --filter @mepapp/ui typecheck`.

REPORT: Status word, the verbatim summary lines of both commands, any bug found.
