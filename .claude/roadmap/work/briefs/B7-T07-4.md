# Brief B7-T07-4 (ui): fixes of the review of the live overlay hook

Read .claude/roadmap/rules.md first. Escalation rule: if reality differs from this brief, stop and return NEEDS_CONTEXT. Do not work around it. Do not run prettier. Do not commit.

## GOAL
Fix 4 findings in `packages/ui/src/useRiserFlowInputs.ts`. Read the whole file first (it is about 190 lines). The hook keeps an overlay of the live riser networks of all open documents (`overlay`, class `LiveRiserOverlay` in `riserFlowSync.ts`), a snapshot `activeDoc` (`{ id, projectUuid }` of the active document) and the helper `captureDocument(scene, documentId, projectUuid)`.

## CONTEXT (the four findings)
1. A document can get a new projectUuid with no `run` (the menu "Use as copy" calls `commitProjectUuid`; the scene only emits `documentsChanged`). Then the `activeDoc` snapshot has the old uuid, and on the next switch `captureDocument` writes the document's networks under the OLD uuid. Also a new document gets its uuid after the first run (`loadFromPdf`), and nothing schedules a run when the uuid arrives.
2. `run` returns early (summaries not read yet, or `computeRiserFlow` returns null because the shown page is not a sheet of the building) before the overlay entry of the active document is refreshed. The Building dialog now reads only the overlay, so it can show stale data of the active document.
3. `onSwitch` and `onDocuments` run inside scene event listeners with no try/catch. A throw there stops the remaining events of `activateInternal`. `run` has a try/catch with `console.warn('Riser flow inputs failed', error)`.
4. (No change; decided by the lead: no unit test of the hook, the browser check b7-t07-check covers it.)
