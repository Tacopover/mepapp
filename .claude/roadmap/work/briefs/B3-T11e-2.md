## CONTEXT: what changed in the UI (read packages/ui/src/components/LevelSheetsPane.tsx, BuildingSheetsPane.tsx, ManageBuildingsDialog.tsx)
- Placed sheets (stored in the building) now show in `[data-testid="level-sheets"]` for the SELECTED level in the tree (the dialog opens with the level of the active sheet, else the first level). Each sheet row is `[data-testid="page-row"]` inside a `[data-testid="pdf-group"]` (all sheets of one PDF on this level share one group). Row has `<b>fileName</b>`, `sheet-status`, `open-sheet`, `relink-pdf` (only when missing), a select `aria-label="Move {file} page {N} to level"` (first option "Move to…", then the other levels), and a `Remove` button (removes ONE sheet). To see another level click its tree item `[role="treeitem"][data-kind="level"]`; the building node `[role="treeitem"][data-kind="building"]` shows all sheets.
- The add pane `[data-testid="sheets-pane"]` (heading "Add PDFs") holds ONLY added PDFs that wait with unassigned pages: a `pdf-group` per PDF, `page-row` per UNASSIGNED page, select `aria-label="Level for {file} page {N}"` ("Not assigned" + levels). When a page gets a level it leaves this list and shows in its level's `level-sheets`. A PDF whose pages are all assigned disappears from the add pane. `sheets-totals` shows only while a waiting PDF exists. There is no "Remove sheets" button any more (use the per-row Remove). "Remove from list" stays on waiting PDFs.
- Words: chip texts: OK, Missing, No access, Not saved yet, No summary, Out of date, May be a copy (data-status values are unchanged). Button for a sheet with no path: "Choose file…" (was "Pick the file again…"). Relink-confirm block `relink-confirm` appears under the row.
- `data-testid="sheets-notice"` is still the notice (now rendered once at the top of the panel).
