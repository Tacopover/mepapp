CONTEXT: The Manage Buildings dialog (B3) shows one open building file. All logic lives in a plain class so vitest (no DOM in this package) can test it. The recent list functions are in `packages/ui/src/recentBuildings.ts` (`loadRecentBuildings`, `saveRecentBuildings`, `addRecentBuilding`, `removeRecentBuilding`, type `RecentBuilding`). The memory store has `capabilities.persistent === false`.

EXACT SHAPES:

```ts
// buildingController.ts
import type { BuildingFile } from '@mepapp/core';
import type { BuildingRef, BuildingStore, FileAccess, FileTarget } from '@mepapp/platform';
import { type RecentBuilding } from './recentBuildings.js';

export type SheetStatus = 'ok' | 'pdf-missing' | 'no-access' | 'not-stamped' | 'no-summary' | 'old-summary' | 'copy-suspected';

export interface OpenBuilding {
  file: BuildingFile;
  revision: string;
  store: BuildingStore;
  ref: BuildingRef;
  /** True while a write is queued or running. */
  dirty: boolean;
  sheetStatus: Record<string, SheetStatus>;   // always {} in B3-T02
}

export interface BuildingState {
  building: OpenBuilding | null;
  recent: RecentBuilding[];
  /** A sentence for the user (a failure or a lost change), or null. */
  message: string | null;
  /** True while create/open/openRecent runs. */
  busy: boolean;
}

export interface BuildingControllerArgs {
  fileAccess: FileAccess;
  makeStore: (ref: BuildingRef) => BuildingStore;
  /** Storage for the recent list; defaults to localStorage (see recentBuildings.ts). */
  storage?: Pick<Storage, 'getItem' | 'setItem'>;
  /** Defaults to crypto.randomUUID. */
  newId?: () => string;
}

export const BUILDING_FILE_TYPES: FileTypeFilter[]  // [{ description: 'Building file', mimeType: 'application/json', extensions: ['json'] }]

export class BuildingController {
  constructor(args: BuildingControllerArgs);
  getState(): BuildingState;                       // returns the SAME object until a change (needed by useSyncExternalStore)
  subscribe(listener: () => void): () => void;
  /** Cancel by the user = resolves with no change. */
  create(name: string): Promise<void>;
  open(): Promise<void>;
  openRecent(entry: RecentBuilding): Promise<void>;
  forgetRecent(id: string): void;
  /** Opens the building that a store already holds (used by the dev hook of the web app). */
  adopt(store: BuildingStore, location?: string): Promise<void>;
  update(change: (file: BuildingFile) => BuildingFile): Promise<void>;
  close(): void;
  dismissMessage(): void;
}
```

Behavior (follow exactly):
- `create(name)`: trim name; blank becomes 'New building'. `file = emptyBuilding(newId(), name)`. `json = serializeBuildingFile(file)`. FIRST await is `fileAccess.saveFileAs(suggested, BUILDING_FILE_TYPES, new Blob([json], { type: 'application/json' }))` with `suggested = <name with any of \ / : * ? " < > | replaced by '-'>.building.json` (a browser grants a picker only to a fresh gesture, so do no other await before it). `undefined` result = cancel, no state change. `location = typeof (saved.target as {path?: unknown} | undefined)?.path === 'string' ? that path : saved.name`. `ref = { id: file.id, name, location }`. `store = makeStore(ref)`. Then `loadInto(store, ref, json)` (below). Errors set `message = 'Could not create the building: <error message>'`.
- `open()`: FIRST await is `fileAccess.openFile(BUILDING_FILE_TYPES)`; `undefined` = cancel. `text = await opened.file.text()`; `parsed = parseBuildingFile(JSON.parse(text))`; location as in create (from `opened.target`, else `opened.file.name`); `ref = { id: parsed.id, name: parsed.name, location }`; `store = makeStore(ref)`; `loadInto(store, ref, text)`. A `BuildingFileError` or JSON error sets `message = 'This is not a valid building file: <message>'`; another error sets `'Could not open the building: <message>'`.
- `loadInto(store, ref, text)`: if `!store.capabilities.persistent` the store holds no file of its own, so `await store.write(text)` unconditionally. Then `stored = await store.read()`; if undefined, write `text` and read again. Parse `stored.json`; set `building = { file, revision: stored.revision, store, ref: { id: file.id, name: file.name, location: ref.location }, dirty: false, sheetStatus: {} }`; add `{id,name,location}` of the ref to `recent` with `addRecentBuilding` and persist with `saveRecentBuildings(list, storage)`; clear `message`.
- `openRecent(entry)`: `store = makeStore(entry)`; `stored = await store.read()`; if undefined, or its parsed `id !== entry.id`, set `message = 'The building file "<entry.name>" was not found. Use Open building to find it.'` and return. Otherwise set the open building as in loadInto and move the entry to the front of the recent list.
- `forgetRecent(id)`: `removeRecentBuilding`, persist, notify.
- `adopt(store, location = 'dev')`: read the store; if undefined set `message = 'The store holds no building.'`; else parse and set the open building with `ref = { id, name, location }`; do not touch the recent list.
- `update(change)`: no open building = resolve. `next = change(current.file)`; if `next === current.file` resolve. Apply the new file to the state AT ONCE (optimistic) with `dirty = true`, then write `serializeBuildingFile(next)` with the current revision through a promise chain, so writes run one after another and each uses the revision returned by the one before. A queued write writes the newest file of the state; skip a write whose JSON equals the last written JSON. On success: store the new revision; `dirty = false` when no write is left. On `StoreConflictError` (check `error.name === 'StoreConflictError'` or `instanceof`): re-read the store, parse it, replace `file` and `revision` with it, drop all queued writes, set `message = 'The building file changed on disk. Your last change was not saved.'`, `dirty = false`. On another error: set `message = 'Could not save the building: <message>'`, keep the file in the state, `dirty = false`. The returned promise resolves when its write ended (never rejects).
- `close()`: `building = null`, `message = null`. `dismissMessage()`: `message = null`.
- `getState()` is stable: replace the state object (`this.state = { ...this.state, ... }`) only on a change, then call the listeners.
- The constructor loads `recent` with `loadRecentBuildings(storage)`.

```ts
// useBuilding.ts
import { useEffect, useMemo, useSyncExternalStore } from 'react';
export type UseBuilding = BuildingState & Pick<BuildingController, 'create' | 'open' | 'openRecent' | 'forgetRecent' | 'adopt' | 'update' | 'close' | 'dismissMessage'>;
export function useBuilding(args: { fileAccess: FileAccess; makeStore?: (ref: BuildingRef) => BuildingStore }): UseBuilding & { available: boolean };
```
`available` is `makeStore !== undefined`. When `makeStore` is undefined, use a `makeStore` that throws `new Error('Buildings are not available in this build.')`. Create the controller once with `useMemo` keyed on `args.makeStore` and `args.fileAccess`; read the state with `useSyncExternalStore(controller.subscribe, controller.getState)`; bind the methods (`controller.create.bind(controller)` etc., created in the same `useMemo`). Note: `subscribe` and `getState` must be bound too.

Tests (`buildingController.test.ts`, vitest, no DOM): use `MemoryBuildingStore` (from `@mepapp/platform`), a fake `FileAccess` object (cast: `{ saveFileAs, openFile } as unknown as FileAccess`), and a fake storage `{ getItem, setItem }`. Cover: create (writes the file through saveFileAs; the open building has the name and an empty level list; recent list gets the entry; a blank name; a cancel leaves state unchanged), open (valid file; invalid JSON gives the message; a building with levels), openRecent (found, not found message, other id message), forgetRecent, update (optimistic file at once; revision changes after the promise; two quick updates write in order with no conflict; a conflict by writing to the store behind the controller's back gives the message and reloads the file; no-op change returns without write), close, adopt, getState stable between calls without change, subscribe notified and unsubscribe works. A permanent-store case is not needed.
