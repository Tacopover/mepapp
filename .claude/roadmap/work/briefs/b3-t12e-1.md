# Brief B3-T12e-1: Level export after the Save question uses the fresh building

Read .claude/roadmap/rules.md first. Work only in /root/MepApp/.claude/worktrees/buildings-model. Do not commit. Do not run prettier. No heredocs, one command per Bash call.

## GOAL
After the user answers "Save" in the "Save before export" question, the Level or Building export must use the building file as it is AFTER the save. Today it uses `ask.building`, which was read before the save, so a sheet that the save just linked (projectUuid set by `summaryAfterSave`) still shows `projectUuid: null` and the export warns "the document has no id yet". Also, when the save works but the document still has no id in the file, show a status message instead of exporting nothing quietly.

## CONTEXT
- `packages/ui/src/App.tsx` ~line 2265: `exportSaveAsk && <SaveBeforeExportDialog ... onSave>`. It calls `await handleSave()`, then checks `projectUuidInFile`, then `runExportQuantities(ask.scope, ask.building)`. `ask.building` is stale.
- `saveDocument` (App.tsx ~1058) already calls `writeBuildingSummary` -> `summaryAfterSave` (packages/ui/src/buildingContext.ts), which links unlinked matched sheets in the building store and then `buildingHook.reload()`.
- `handleExportQuantities` (App.tsx ~1130) reads the building like this: `const stored = await buildingStore.read(); building = stored === undefined ? undefined : sortLevelsByElevation(parseBuildingFile(JSON.parse(stored.json)));`
- `saveDocument` returns `Promise<void>`; `handleSave = () => saveDocument(false)`. Its early return (file task busy) and its catch path mean "not saved".
